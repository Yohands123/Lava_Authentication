# Phase 7A local data governance

Study approval is pending. All new research controls remain inside the existing localhost-only Lab. The normal product still offers passkeys without research. The active interaction may use temporary local pointer buffers for existing physics/feature extraction; optional study retention/export requires the pre-attempt consent snapshot. Checking consent after an attempt begins cannot retrospectively create its research record.

The Lab retains at most 32 opted-in exports in page memory. It now provides a full latest-record preview, attempt history and optional companion session-manifest download. No new upload endpoint, persistence, background listener or monitoring service exists. Closing the page or withdrawal clears this memory. The manifest contains page-relative consent/configuration observations, declared labels/devices and attempt/session codes; its supervision status is explicitly UNVERIFIED. It is not an exact wall-clock sample log or an independent consent attestation. A coordinator must supply the separately reviewed supervision manifest; old metadata is not reconstructed.

Pointer dynamics and pseudonymous linkage codes can be identifying. Keep downloaded raw trajectories, private manifests, derived records, cohort maps and candidates under ignored `ml/private/`. The Phase 7 dataset is separate at `ml/private/phase7a/`; existing Phase 5/6 data is preserved. No passwords, account names, credentials, cookies, camera frames, IPs or passkey material enter model predictors. Environment hints remain a distinct advisory channel; declared devices/environments are strata and QA metadata, not behavioral model inputs.

`npm run phase7:import -- <private-export.json>` validates by default. Explicit `--apply` requires the machine protocol's owner-approved state and writes only the fixed Phase 7 private folder. Inputs are bounded and constrained to private files. Exact v3 export validation, duplicate/label checks and opt-in provenance use the existing importer. The separate supervision manifest is still required before evaluation: importing an unverified declaration cannot establish a genuine human.

Use `npm run ml:phase5:withdraw -- --participant STUDY_CODE` for a dry run; add `--apply` only for the participant's requested deletion. The existing command scans supported local raw/batch/session-manifest/JSONL formats across private research. It writes the global revocation ledger first, removes matching participant data, conservatively invalidates dependent candidates/cohorts/reports/supervision, and preserves final-evaluation locks. Phase 7 evaluation also consults that global ledger, so a surviving file after failed deletion cannot silently re-enter fitting. No real participant withdrawal was run by this task; tests use temporary synthetic copies.

Cleanup now reports `PARTIAL_CLEANUP_REVOKED` with failed-write count/path hashes if a supported deletion fails. Removed-row counts become unknown in that case; planned counts are separately labeled. Retry cleanup and confirm supported files are gone. Failure to write the revocation ledger stops deletion; failure to write the final audit can still raise an error and requires manual inspection. Do not equate a revoked record with confirmed physical erasure. The browser similarly distinguishes local deletion from unconfirmed server-history deletion.

The tool cannot retract unknown Downloads copies, external backups, arbitrary binary formats or published aggregates. Owners must delete external copies and supersede affected public summaries. Sensitive minimal revocation hashes prevent reimport but need their own justified access/retention policy. Candidate invalidation is conservative; deleting training rows does not unlearn coefficients. Readiness, approval and final-use state must be reviewed again after withdrawal or lineage changes.

No contact list or recruitment records are created. Data access is limited to the owner and explicitly approved evaluators on local private copies. The proposed 30-day retention is a coordinator responsibility pending protocol approval. No scheduling, external transfer or real-person collection was started.
